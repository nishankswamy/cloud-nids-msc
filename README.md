# Deepfake Detection — Cross-Generator Generalization Analysis

A deepfake face detector built with EfficientNet-B0, evaluated not just on standard benchmark accuracy, but on whether it actually generalizes to a **different GAN generator it was never trained on**. Spoiler: it doesn't — and the analysis of *why* is the actual point of this project.

## TL;DR

- Trained a binary real-vs-fake face classifier (EfficientNet-B0) on the [140k Real and Fake Faces](https://www.kaggle.com/datasets/xhlulu/140k-real-and-fake-faces) dataset (FFHQ real photos vs. StyleGAN1/2-generated fakes)
- Achieved **99.78% accuracy, 1.0 AUC** on the held-out test set from the same distribution
- Tested the same model, with no retraining, on a **StyleGAN3**-generated face dataset (different generator, same real-image source)
- Accuracy **collapsed to 47.88%**, and AUC **inverted to 0.285** — worse than random guessing, meaning the model consistently ranked StyleGAN3 fakes as *more* real-looking than genuine photos
- Grad-CAM analysis shows the model attends to plausible facial regions (eyes, nose, mouth) for both real and fake images — ruling out a naive background/border shortcut, but confirming the model learned **generator-specific texture statistics** rather than a general notion of "synthetic face"

## Why this matters

Near-perfect in-distribution accuracy is the norm in published deepfake-detection demos, but it's a well-known trap: models trained on one generator's output frequently fail to generalize to newer or different generators, because they key on narrow artifact signatures rather than semantically meaningful forgery cues. This project reproduces that failure mode directly and empirically, and uses Grad-CAM to show it isn't a spatial shortcut (like a background artifact) — it's something subtler happening within the correct facial region.

## Method

1. **Data pipeline**: PyTorch `ImageFolder` / custom `Dataset`, standard augmentation (flip, color jitter), ImageNet normalization
2. **Model**: EfficientNet-B0 (via `timm`), pretrained on ImageNet, fine-tuned as a 2-class classifier
3. **Training**: AdamW, cosine LR schedule, 5 epochs, batch size 64
4. **Evaluation**: Accuracy, AUC, confusion matrix, ROC curve
5. **Generalization test**: Same trained model evaluated zero-shot on [10k Real vs Fake Faces (StyleGAN3)](https://www.kaggle.com/datasets/troykueh/real-vs-fake-faces-stylegan3) — real images still sourced from FFHQ (holding that variable constant), fakes generated by StyleGAN3 instead of StyleGAN1/2
6. **Interpretability**: Grad-CAM on the final convolutional layer (`conv_head`), visualized for both in-distribution and out-of-distribution samples, across both real and fake predictions

## Results

### In-distribution (StyleGAN1/2 test set)

| Metric | Value |
|---|---|
| Accuracy | 99.78% |
| AUC | 1.0000 |
| Precision/Recall (both classes) | 1.00 |

### Out-of-distribution (StyleGAN3, zero-shot)

| Metric | Value |
|---|---|
| Accuracy | 47.88% |
| AUC | 0.2851 |

The AUC inversion (below 0.5) is the key finding — this isn't the model becoming *uncertain*, it's the model's learned decision rule **flipping direction** on cleaner, more recent-generator output. A plausible explanation: StyleGAN3 was explicitly designed to eliminate the texture-aliasing artifacts present in StyleGAN1/2, and the classifier appears to have keyed on exactly that class of artifact.

See `results/confusion_matrix.png` and `results/roc_curve.png` for the in-distribution results.

### Grad-CAM interpretability

See `results/gradcam_grid.png`. Across both real and fake images, activation consistently centers on the nose, eyes, and central facial region — not on background or image borders. This rules out a naive spatial/border shortcut, but the near-identical attention pattern between real and fake images suggests the model is discriminating on **subtle texture statistics within the correct region**, not on any human-interpretable "forgery cue" (e.g. blending seams, asymmetry). This is a more concerning failure mode than a spatial shortcut, since it can't be caught by inspecting attention maps alone — only by explicit cross-generator testing, as done here.

## How to reproduce

1. Open `deepfake_detection_starter.ipynb` in Google Colab (GPU runtime recommended)
2. Download a Kaggle API token from [kaggle.com/settings/account](https://www.kaggle.com/settings/account) and upload it when prompted
3. Run cells top to bottom — this downloads the dataset, trains the model, and produces all evaluation metrics
4. For the generalization test, download the StyleGAN3 dataset (`troykueh/real-vs-fake-faces-stylegan3`) and run the OOD evaluation cells
5. For Grad-CAM, run the interpretability cells at the end of the notebook

## Limitations & next steps

- Only tested against one alternate generator (StyleGAN3); a broader benchmark (Celeb-DF, FaceForensics++, diffusion-based fakes) would give a fuller generalization picture
- Frequency-domain (FFT) analysis of both generators' outputs would help confirm the texture-statistics hypothesis directly, rather than inferring it from Grad-CAM
- Training with data augmentation across multiple generators, or adversarial/robustness-focused training, is a standard mitigation worth testing against this exact failure mode
- A larger backbone (EfficientNet-B4) might shift the specific artifacts learned, but is unlikely to fix the underlying generalization problem without deliberately diverse training data
